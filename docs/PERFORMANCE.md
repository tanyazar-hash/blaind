# Производительность и адаптивность Блаинд

Проверено 11.11.2026. Исходная фишка `shakhmatnaya-figura.glb` сохранена без изменения. Тестовая страница четырёх тузов, её CSS, JS и отдельная модель удалены. Изображения турниров, используемые ARENA, сохранены, как и данные / Auth / Supabase / серверные API.

## Ресурсы и отрисовка

- Исходная модель: 14 928 280 байт, 332 146 треугольников, три JPEG 2048×2048. В production передаются производные того же GLB: desktop 771 012 байт / 73 070 треугольников, mobile 318 876 байт / 23 250 треугольников. Логотип на обеих сторонах — исходный SVG; две его плоскости добавляют 4 треугольника при отрисовке.
- LOD создаётся упрощением с ограничением геометрической ошибки, Meshopt-сжатием и WebP-текстурами 1024 / 512. Устройства до 900px, save-data и ограниченные CPU/RAM получают мобильный LOD. Загружается только одна версия.
- DPR ограничен 1–1.25 на мобильных / слабых устройствах и 1.75 на ПК. Сохраняются исходные материалы, освещение, тональное отображение и отражения. RoomEnvironment сначала рендерится в cubemap 64/128, затем PMREM использует её размер вместо фиксированных 256. На медленных кадрах разрешение буфера снижается в ограниченных пределах.
- Падение рассчитывается по реальному прошедшему времени, а не сумме ограниченных dt. Вращение и три отскока сохранены. Мобильный центр — половина доступной ширины экрана. Падение перенесено на композиторную анимацию перемещения с той же баллистикой и тремя отскоками; вращение синхронизировано по её времени. Перед стартом прогревается WebGL. Мобильная сцена размещена в координатах документа и сохраняет расстояние до текста при прокрутке, без обрезающих масок.
- На телефоне фишка видна в первом и контактном разделах; в остальных разделах уходит за экран. На ПК восстановлены все пять исходных положений, включая левую позицию в «Нашем подходе» и правую в «Событиях»; пороги переходов и размеры соответствуют исходному сценарию. Позиции фиксированы для разделов, пружинный переход зависит от времени. Прямой привязки трансформации к scroll progress нет.
- WebGL не перерисовывается при неизменной позе, за пределами экрана или в скрытой вкладке. Повторный resize не пересоздаёт буфер без изменения размеров. Ненужные RAF отменяются, GPU-ресурсы освобождаются при окончательном уходе со страницы. При ошибке загрузки / WebGL остаётся прежний логотип; во время успешной загрузки замены фишки нет.
- JS собирается esbuild: минификация, tree shaking, общие ESM-модули и отложенный отдельный 3D-chunk. CSS минифицируется только в `public/`. Шаблоны и исходники остаются читаемыми. Хешированные чанки и модели имеют immutable cache; API / приватные сессии так не кэшируются.
- WOFF2 сохраняют все глифы и начертания исходных шрифтов: 67 912 → 53 716; 134 796 → 106 396; 131 644 → 104 068 байт. Оригиналы и лицензии сохранены. Файлы созданы FontTools с Brotli 1.1.0; при замене шрифтов нужен повторный экспорт WOFF2.
- Фотографии «Атмосферы» получили AVIF-варианты тех же размеров, с WebP fallback через picture. Суммарно AVIF около 1,0 МБ против 1,3 МБ WebP. Загрузка остаётся ленивой, размеры заданы, приоритет фотографий ниже текста / шрифтов. Оригиналы JPEG и сценарии галереи сохранены.

## Воспроизведение

Node.js 22.x, `npm ci`, `npm run build`, `npm test`. `npm run dev` — сервер исходников с API. Для проверки именно минифицированной production-версии тесты запускают свой сервер с корнем `public/`.

`npm run assets:prepare` заново создаёт LOD / manifest, vendored Meshopt decoder и AVIF. Это отдельный ресурсоёмкий шаг после замены оригиналов, а не часть каждой сборки. Результаты хранятся в Git. Сборка использует готовые файлы. Лицензии Three.js, шрифтов и Meshoptimizer сохраняются.

Браузерные команды: `npm run test:browser`, `node tests/site-browser.cjs`, `node tests/legal-browser.cjs`, `node tests/entrance-browser.cjs`, `npm run test:performance`. Нужен системный Chromium `/usr/bin/chromium`; Playwright зафиксирован в devDependencies.

## Результаты

Chromium в Linux, программный WebGL. Эмуляция viewport / DPR / touch, а не физические телефоны:

- Android 320×740 и 360×800;
- iPhone 14 Pro 393×852 @3, iPhone 17 402×874 @3;
- Pixel 412×915 @2.625;
- планшет 768×1024, телефон в альбомной ориентации 844×390, iPad 1024×768;
- ПК 1440×900 и 1920×1080.

На каждом размере проверены production-страницы главной, ARENA, «Атмосферы», документов и входа в админ-панель: отсутствие горизонтального overflow и HTTP / JS ошибок. На главной — настоящий GLB, центрирование, отсутствие наложения на первый экран, уход модели в средних разделах и место в контактах. Проверены меню, AVIF, reduced motion и отказ загрузки GLB. Отдельные существующие браузерные suite также проверяют вход, CRUD, изображения и mobile/logout панели, полный рейтинг ARENA и его фильтры, галерею «Атмосферы», свайп, фокус, поведение при ошибках изображений и повторные анимации страниц. Служебная suite проверяет вход, CRUD, изображения, live totals, мобильный редактор и logout на локальных Auth / PostgreSQL fixtures.

Отдельный холодный запуск: сеть 1,28 Мбит/с, latency 150 мс, замедление CPU ×4, DPR 3, мобильный LOD. Измерено: LCP 1404 мс, CLS 0,00123, полная готовность сцены с окончанием падения 11 508 мс, ресурсы decodedBodySize 1 206 779 байт. Это лабораторный результат, не гарантия для всех сетей / устройств. `decodedBodySize` — распакованный объём, а не трафик с CDN-сжатием. Исходный вариант в той же среде: 16 762 198 байт, готовность 138 991 мс; время сильно зависело от программного GPU и старого накопления dt. Измерения не являются полевыми Core Web Vitals и не заменяют физическое iOS / Android тестирование.

Установка WebKit 26.0 предпринята, но официальные загрузки `cdn.playwright.dev` / `playwright.download.prss.microsoft.com` отклонены сетевой политикой (403 Domain forbidden). Реальный Safari / WebKit и физические iPhone в этой среде не проверены. Доступ к production Vercel также необходимо проверять отдельно от Git push.

Регрессия движения: `node tests/chip-motion-browser.cjs` проверяет настоящий WebGL с включённой анимацией, форму падения и отскоки, пять исходных desktop-позиций, уход мобильной фишки и возврат в свободный слот, прокрутку вниз и вверх. `tests/performance-browser.cjs` отдельно проверяет раскладку в reduced motion; эта проверка не заменяет тест движения.

После исправления сценариев фишки контроль CPU ×4 / 1,28 Мбит/с / 150 мс: полная готовность 15 883 мс, от появления модели до завершения падения 1 949 мс, горизонтального overflow нет. Мобильная сцена ограничена свободным слотом (331px в первом экране / 200px в контактах), а не высотой всего документа. Desktop-сценарий снова использует все пять исходных позиций.
