# Передача сайта «БЛАИНД»

## Структура и ограничения

Главная — короткая презентация и три карточки. Рейтинг, турниры и аренда
доступны на отдельных страницах. «О нас» и фотоархив удалены, исходные
фотографии сохранены. Меню: Главная, Рейтинг, Турниры, Аренда столов, Связаться.
Юридические страницы — правила клуба и персональные данные; старые URL
перенаправляются к актуальным страницам.

Цены, контакты, клубные условия и реальные данные не менялись. Нет денежных
ставок; депозит предназначен только для напитков и закусок. Запись и бронирование
ведут на существующий официальный контакт. Первые 18 мест выделяются по
официальному рейтингу независимо от поиска и сортировки.

На ПК исходная фишка появляется с падением/отскоком и вращается мышью с
инерцией; доступны стрелки клавиатуры. На смартфонах и планшетах 3D-ресурсы
не загружаются. Текст не скрывается за анимациями. В покое, вне экрана и
в скрытой вкладке непрерывного рендеринга нет. Подробности: PERFORMANCE.md.

## Разработка и проверка

Node.js 22.12+ (22.x), `npm ci`, `npm run build`, `npm test`.
`npm run dev` запускает исходные страницы/API на порту 8020.
Для облачной среды с HTTP-прокси: `NODE_OPTIONS=--use-env-proxy npm run dev`.
Сборка `public/` не содержит серверного кода и файлов окружения.

Браузерные проверки используют `/usr/bin/chromium`; в CI задаётся
`PLAYWRIGHT_BUNDLED_CHROMIUM=1` после установки Chromium через Playwright.

- `npm run test:browser`: вход/выход, CRUD, загрузки, сессия и живые обновления.
  Только локальная PGlite и тестовая авторизация; даты турниров создаются в будущем.
- `node arena/tests/browser.cjs`: фильтры, сортировка, live, сбои/повторы,
  безопасные заголовки, пустые коллекции и изображения.
- `node tests/site-browser.cjs`: основные страницы, 320–1920px, меню, контакты,
  цены, первые 18 мест и отсутствие наложений.
- `node tests/chip-motion-browser.cjs`: жизненный цикл 3D и мобильная загрузка.
- `npm run test:accessibility`: axe для 18 состояний страниц и админки.
- `npm run test:polish`: клавиатура, fallback, ошибки/восстановление админки
  и загрузка изображения с задержкой более 20 секунд.
- `node tests/legal-browser.cjs`, `node tests/entrance-browser.cjs`: юридические
  ссылки, печать, reduced motion, история и навигация без JavaScript.
- `npm run test:performance`: десять размеров и холодная загрузка CPU ×4.
- `node tests/hosting-browser.cjs`: production-сборка под `/` на файловом сервере.
  Повторить после `SITE_BASE_PATH=/blaind/ STATIC_HOSTING=1 npm run build`
  с теми же переменными окружения. Затем восстановить `npm run build`.

Supabase Auth, RLS, CAS и HttpOnly cookies сохранены. CRUD проверяется локально
с настоящими SQL-политиками. Service-role ключ не нужен. Доступность production,
настоящую авторизацию администратора и права конкретного пользователя нельзя
подтвердить локальными фикстурами; не вводите пароли в чат и не записывайте тестовые
данные в рабочую базу. Первичная настройка владельцем описана в ADMIN_SETUP.md.

## Публикация

GitHub Actions запускает проверки и публикует GitHub Pages. Существующая
интеграция Vercel сохраняется. Публикации проверяются `tests/deployed-browser.cjs`
без записи в базу: публичные страницы, live-рейтинг, загрузка GLB на ПК,
отсутствие canvas на мобильном, переход админки Pages на Vercel и форма входа.
Vercel Deployment Protection не должна закрывать публичный сайт SSO до входа
клуба. Конфигурацию публикации и Supabase меняет только владелец.
