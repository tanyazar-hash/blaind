# Передача проекта «БЛАИНД»

Контрольная проверка: 12 ноября 2026. Сохранены чёрно-золотая концепция,
семь исходных фотографий, оригинальная GLB, пять desktop-позиций фишки,
мобильные слоты, структура страниц и данные Supabase.

## Изменения финальной полировки

- Общие стили перехода к содержимому и фокуса, тёмные нативные элементы форм.
  Контраст номеров рейтинга и мелкой подписи повышен в рамках существующей палитры;
  ссылка разработчика различима без опоры только на цвет.
- Escape в мобильном меню возвращает фокус на кнопку. Широкая таблица политики
  доступна с клавиатуры. Смена reduced motion во время раскрытия блока немедленно
  завершает переход и не оставляет обрезанный текст.
- Админка сохраняет недоступность граничных кнопок перестановки после загрузки,
  сохранения и ошибки. Выбранная запись выделена; поля и кнопки имеют понятные
  имена. Сетевые сбои и HTML вместо ответа API показывают понятное сообщение,
  ожидание обычного запроса ограничено 20 секундами, загрузки изображения —
  двумя минутами, чтобы не обрывать медленную передачу файла. Сессии, CSRF, версии документов и RLS не ослаблены.
- GPU-ресурсы освобождаются и при потере WebGL-контекста, и при сбое загрузки
  текстуры. Общая геометрия/материалы/текстуры освобождаются один раз. Падение,
  отскоки и переходы между разделами сохранены.
- Убраны отдельные шаблонные формулировки, исправлен повтор «клуба клуба» в метаописании.
  Название и Барнаул приведены к одному виду без добавления новых контактов,
  услуг, цен или юридических реквизитов.

## Воспроизводимые проверки

Node.js 22.12+ в пределах ветки 22.x, `npm ci`, затем `npm run build`.
Chromium локально — `/usr/bin/chromium`; в CI используется браузер Playwright.

| Команда | Что проверяет |
| --- | --- |
| `npm test` | 27 тестов данных, Auth-контрактов, PostgreSQL/RLS, прав, CAS и ресурсов |
| `npm run test:browser` | Вход, CRUD, загрузку/удаление изображений, живые счётчики, сессию и logout на локальных fixtures |
| `npm run test:accessibility` | Axe WCAG A/AA, 2.1/2.2 AA и best practices: 24 состояния публичных страниц и редакторов при 390/1440px |
| `npm run test:polish` | Клавиатуру, смену reduced motion, ошибки галереи, потерю настоящего WebGL-контекста и восстановление админки после сбоя |
| `node tests/site-browser.cjs` | Общие шапку/подвал, сетку, меню, аккордеоны и галерею на ширинах 320–1440px |
| `node tests/legal-browser.cjs` | Все документы, ссылки, печать и чтение без JavaScript |
| `node tests/entrance-browser.cjs` | Анимации при открытии и возврате по истории, reduced motion, выравнивание первых экранов |
| `node tests/chip-motion-browser.cjs` | Реальную GLB, падение/отскоки, пять desktop-позиций, mobile уход/возврат и обратный скролл |
| `npm run test:performance` | 10 размеров от 320px до 1920px, touch/DPR, Android/iPhone/iPad viewport, холодную загрузку при CPU ×4 и медленной сети |
| `node tests/hosting-browser.cjs` | Готовую сборку на обычном файловом сервере; запускать с теми же параметрами, что использовались при сборке |

ARENA дополнительно проверена `arena/tests/browser.cjs`: поиск, фильтры, сортировка,
глобальные места, часовой пояс, афиши, ошибки/повторная загрузка и пустые коллекции.
`atmosphere/tests/browser.cjs` проверяет все семь кадров, пропорции, стрелки, свайп,
фокус, Escape, оригиналы без JS и восстановление после отказа изображения.
Эти suite требуют запущенного тестового сервера: задайте `ARENA_BASE_URL` и
`ATM_BASE_URL`. В проверке использовался локальный read-only снимок из репозитория.

В GitHub Actions перед публикацией выполняются unit/RLS, accessibility и polish
регрессии, затем сборка под фактический префикс Pages и её browser smoke test.
После публикации отдельно проверяются настоящие Pages и Vercel: все публичные
страницы и reload, фотографии, локальные шрифты, GLB и живой рейтинг. Production
не заполняется тестовыми записями. Инструкции размещения — в `HOSTING.md`.

## Что подтверждает владелец

Адрес backend должен быть доступен до входа в приложение: если Vercel Authentication
перенаправляет на SSO Vercel, production-проверка завершится явной ошибкой.
Изменение Deployment Protection не заменяет и не отключает Supabase Auth/RLS.
Для окончательной приёмки нужен вход владельца существующим Auth-аккаунтом;
его пароль не запрашивается в чате и в тестах production не используется.

В документах остаются исходные явные пропуски: реквизиты исполнителя, оператор
персональных данных и его контакт, режим работы и официальный канал претензий.
Их заполняет владелец по фактическим сведениям; подробности — `docs/LEGAL_REVIEW.md`.
До этого юридическое наполнение нельзя считать завершённым.

Мобильные проверки — эмуляция viewport, touch и DPR в Chromium. Физические iPhone,
Android и Safari/WebKit в этой среде не проверены: официальные загрузки WebKit
ранее блокировались сетевой политикой. Лабораторные метрики не являются полевыми
Core Web Vitals; замеры и условия описаны в `docs/PERFORMANCE.md`.
