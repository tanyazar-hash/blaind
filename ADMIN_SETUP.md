# Администрирование BLΛIND ARENA

Панель: `/admin`. Ссылка «Управление» расположена под подвалом главной страницы и ARENA. Публичный дизайн и 3D-анимации сохранены.

## Подключение Supabase и Vercel

1. Создайте проект Supabase. В SQL Editor выполните сначала `supabase/schema.sql`, затем `supabase/seed.sql`. Второй файл добавляет исходные данные и не перезаписывает существующие. SQL можно выполнять повторно. Бакет `arena-images` создаётся автоматически.
2. На своём компьютере с Node 22 выполните `npm ci`, затем `npm run admin:secrets`. Введите согласованный пароль в скрытом приглашении. Скрипт создаст `.env.admin.local` с scrypt-хешем и случайным секретом сессий; пароль не сохраняется. Файл исключён из Git. Не публикуйте его и не присылайте ключи в чат.
3. В Vercel → Settings → Environment Variables добавьте для Production:

| Переменная | Значение |
| --- | --- |
| `SUPABASE_URL` | URL созданного проекта вида `https://….supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный `service_role` ключ проекта Supabase; никогда не anon/publishable и не переменная с префиксом PUBLIC |
| `ADMIN_USERNAME` | `admin` |
| `ADMIN_PASSWORD_HASH` | Полное значение из `.env.admin.local`, включая символы `$` |
| `ADMIN_SESSION_SECRET` | Значение из `.env.admin.local` |
| `APP_ORIGIN` | `https://blaind-tanyazar-hashs-projects.vercel.app` |

4. Один раз выполните Redeploy после подключения переменных. Репозиторий содержит `vercel.json` с командой `npm run build`, каталогом `public` и маршрутами `/arena` и `/admin`. Если в настройках проекта вручную задан другой Output Directory, уберите это переопределение. Используется Node 22 и две серверные функции.
5. Откройте `/admin`, войдите и измените тестовую запись. Проверьте её на `/arena` в другом окне. Изменения после этого не требуют деплоя: активные публичные вкладки обновляются раз в 4 секунды, при фокусе и сразу после сохранения в другой вкладке того же браузера.

Без подключения базы публичная ARENA показывает прежние демонстрационные данные, а администрирование закрыто. При ошибке подключённой базы API возвращает ошибку, а уже открытая публичная страница сохраняет последний успешно загруженный вид. Код не подменяет реальные данные демонстрационными при сбое базы.

## Локальная работа

Создайте игнорируемый `.env.local` с `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`; `.env.admin.local` создаётся скриптом выше. `npm run dev` читает оба файла и запускает сайт на порту 8020. Для локальной работы не задавайте production `APP_ORIGIN`; иначе проверка Origin корректно заблокирует локальные изменения.

Для начального заполнения вместо SQL-файла можно выполнить `node --env-file=.env.local scripts/seed.mjs`. Скрипт не перезаписывает данные.

`npm test` проверяет реальные SQL-миграции и операции на PostgreSQL через PGlite в отдельном временном каталоге: вход, CSRF, сессии, ограничения попыток, CRUD, изображения, конфликты и сохранность после закрытия/повторного открытия базы. `npm run test:browser` требует доступный Playwright и Chromium (`/usr/bin/chromium`) и проверяет интерфейс на временной тестовой базе. Production Supabase в тестах не изменяется. `npm run build` проверяет синтаксис и собирает только публичные ресурсы; серверный код, конфигурация и секреты в `public` не копируются.

## Защита и эксплуатация

- Пароль проверяется только сервером через scrypt. Случайный токен сессии хранится в HttpOnly SameSite=Strict cookie, на Vercel — Secure с префиксом `__Host-`; в базе хранится HMAC, а не токен. Срок сессии — 8 часов. Выход удаляет серверную сессию. Смена `ADMIN_SESSION_SECRET` отзывает все сессии.
- Все записи и загрузки требуют серверную сессию, правильный Origin и CSRF-токен. Вход ограничен шестью попытками за 15 минут на IP; счётчик общий для серверных экземпляров и хранится в базе.
- Таблицы закрыты RLS для посетителей. Серверный service_role ключ нужен только функциям, не передаётся браузеру. Изображения публичны по URL, загрузка и удаление доступны только серверу.
- Изображения: JPEG/PNG/WebP, до 3 МБ и 20 Мп, без SVG и анимации. Проверяются сигнатура, размеры и тип. Имена случайные. Замена/удаление сначала сохраняет документ, затем удаляет больше не используемый файл. Если Storage недоступен при очистке, сохранённые данные остаются; неиспользуемые файлы можно удалить позже в Supabase Storage. Незавершённые загрузки после аварийного закрытия вкладки могут остаться в бакете.
- Документ сохраняется атомарно с проверкой версии. Конфликт не перезаписывает чужие правки: ваш черновик остаётся на экране. Перед обновлением данных скопируйте нужные поля из черновика. Панель предупреждает об уходе с несохранёнными изменениями.
- Настройте резервные копии Supabase согласно своему тарифу. Не удаляйте проект/таблицы при повторном деплое. Для собственных дополнительных пользователей и ролей понадобится расширение текущей модели одного администратора.

Секреты отсутствуют в репозитории. Подключение реального Supabase, production-вход и production-загрузка требуют завершающей проверки после настройки переменных владельцем проекта.
